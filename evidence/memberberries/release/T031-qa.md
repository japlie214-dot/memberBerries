## Diff Review

Hypotheses checked for this pass: (1) base_url accepts anything other than exactly http://127.0.0.1:<port>; (2) statementStatusUrl can reach a non-statements path or another host; (3) plaintext curl can carry the token to a non-loopback host.

1. base_url validation (PASS). validate() at snowflake.rs:54-61 takes the remainder after the exact prefix `http://127.0.0.1:` and requires it to be 1 to 5 ASCII digits with a numeric value from 1 to 65535. Reasoning per new negative case:
   - `http://127.0.0.1:1@evil.example`: remainder `1@evil.example` contains non-digits, refused.
   - `http://127.0.0.1:80/path`: remainder `80/path`, refused.
   - `http://127.0.0.1:` (empty): refused by the empty check.
   - `http://127.0.0.1:0`: parses to 0, refused.
   - `http://127.0.0.1:99999`: parses to 99999, above 65535, refused.
   - `http://127.0.0.1:80.evil.example`: remainder contains `.` and letters, refused.
   - Anything not starting with the exact prefix (for example `http://localhost:1`, `http://evil.example`) gets an empty remainder and is refused.
   - Accepted: `http://127.0.0.1:1` through `http://127.0.0.1:65535`, with no suffix. No `@`, `/` or `.` can survive into the host, so the host is always 127.0.0.1.
2. statementStatusUrl (PASS). snowflake.rs:306-312 requires the value to start with `/api/v2/statements/` and rejects any value containing `..`, `//` or `@`. The request is then built from host_url() plus that path (snowflake.rs:317). `http://evil.example/x`, `/api/v2/statements/../../x`, `/other/path` and `/api/v2/statements/a@evil` all fail the prefix or the character checks. The test a_status_url_outside_the_statements_api_is_never_followed runs all four and asserts no second request is made. The test passed.
3. Plaintext scope (PARTIALLY VERIFIED). The ticket and the first audit say curl gets `proto = "=http"` only when base_url is set (the template at snowflake.rs:388 takes a proto parameter). The call sites at snowflake.rs:301 and :318 pass `self.cfg.base_url.is_some()`, which matches that claim. The code that maps that boolean to the proto string was not re-read in this pass because of the read budget. Combined with item 1, the only base_url that can turn on the http-only path is loopback, so the userinfo route to evil.example is closed. The proto mapping itself is not confirmed by reading it here.
4. Earlier advisories (unchanged, still present): search() silently falls back to lexical on a broken Snowflake config while embed_text errors (memb-rag/src/lib.rs:29); test temp folders (memb-sf-test-*) are left behind; the errors test checks for "ey" rather than the real token. None of these leaks a credential or sends data.

No new P0 or P1 found.
