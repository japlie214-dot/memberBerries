## Diff Review

Hypotheses checked:
1. P1 fix. The status arm (models.rs run()) now calls `inspect(&dir, &v.manifest(), verify)` on the installed build and returns 1 with "NOT ready: ... has a corrupt file" when any state is `FileState::Corrupt`. Confirmed in source. Without --verify, `inspect` yields `Present` (size only), so the arm returns 0. With --verify, a right-size wrong-hash file yields `Corrupt` and the arm returns 1. Confirmed.
2. The new test discriminates. Against the rejected code (no Corrupt check), `status --verify` returned 0 on the corrupt fixture; the test asserts 1, so it fails on the old code. Against the fixed code it passes. Confirmed by reading and by the passing run.
3. Argument parsing. `run()` now walks args[1..]: `--yes`, `--verify`, `--variant <q4|int8>`, anything else returns 2. A missing or unknown --variant value returns 2. No command (`args` empty) returns 2. An unknown command hits the `_` arm and returns 2. `remove` without --yes calls `confirm()`, which returns false when stdin is not a terminal, so the test returns 1 and does not block. Confirmed.
4. Loader identity. `model_identity` iterates `files(directory)`, so the variant's file names are hashed along with bytes. Confirmed by `the_variant_present_in_a_directory_decides_which_files_are_used` and `identity_changes_for_each_model_file`.
5. Width rule. `apply_default` sets MEMB_EMBED_MRL_DIM only when the user has not set it (`set("MEMB_EMBED_MRL_DIM")` guard). Confirmed by the test's second apply_default call keeping 512.
6. Phase-Coverage. The stale sentence "the embedding width stays your `embeddings.mrl_dim`" is gone. The row now says the tier picks the build and width and that a user-set `embeddings.mrl_dim` wins. Confirmed in wiki/Phase-Coverage.md.

## Negative Discriminator Tests

- status_is_not_ready_when_verification_finds_a_corrupt_file_and_arguments_are_checked builds right-size, wrong-content files for the 4-bit build (set_len to the pinned size, not the pinned hash), then asserts:
  - `status` returns 0 (size matches, no hashing: ready). This is the expected behavior without --verify.
  - `status --verify` returns 1 (content mismatch: Corrupt, NOT ready). The rejected code returned 0 here, so this assertion discriminates the P1.
  - `status --bogus` returns 2; `install --variant` (no value) returns 2; `install --variant q8` returns 2; no arguments returns 2; `frobnicate` returns 2.
  - `remove` without --yes returns 1 and the directory remains; `remove --yes` returns 0 and the directory is gone.
- the_variant_follows_the_machine_and_a_machine_below_the_floor_gets_an_explanation: rows with no AVX2/FMA or AVX-512 must yield Err("AVX2"); 8 GB minus 1 MiB must yield Err("RAM"); plan_install without --variant on a weak machine is refused with "cannot run EmbeddingGemma 2 well" and "--variant q4"; with --variant q4 it proceeds; the user's choice wins on a balanced machine.
- the_variant_present_in_a_directory_decides_which_files_are_used: identical bytes in the two variant directories still produce different model identities, so vectors cannot mix.
- a_complete_default_directory_is_used_unless_a_backend_was_chosen: a width the user set (512) is kept; an off-by-one file size makes the directory incomplete again.

These tests use real files and real arguments, not mocks.
