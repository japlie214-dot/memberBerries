# Phase coverage and retirement gate

This is a requirements ledger, not a release claim. **Implemented** means the current (workspace 0.4.0) implementation exists; native host verification is separate. **Replaced** means the design intention is addressed differently. **Open** means the phase software and notes must be retained until implementation or an approved disposition.

| Source | Requirement | Current disposition |
|---|---|---|
| Shared design / 1 | Windows-first Rust daemon and CLI, one project memory across clients | **Replaced:** one binary, stdio per client, one OS-serialized redb store. The optional foreground `memb daemon` is a loop you start yourself (see [Operations](Operations.md)); the daemon has no network listener. A per-user scheduled task for it has been registered on the development machine (row 24); memb and the packages never register one themselves. (The separate `memb web` inspector is a read-only loopback HTTP listener you start yourself; see [Inspector](Inspector.md).) |
| Shared design / 1 | 2 GiB Win32 Job Object and kill-on-close; 1200/1550/1750 MiB governor thresholds and bounded redb cache | **Partial:** 16 MiB configured redb cache, bounded note/query/frame input; `memb daemon` (only) puts itself in a job object with a per-process 2 GiB memory limit (`JOB_OBJECT_LIMIT_PROCESS_MEMORY`); there is no job-wide limit and no kill-on-close, and hook and MCP processes are not capped. The governor thresholds and budget tests remain **open** (a pressure classifier exists in `memb-win` but nothing calls it). Tracked in T020. |
| 1 | Topic/knowledge/claim hierarchy and durable graph | **Implemented:** typed parent links, atomic updates, monotonic IDs, in one unified graph (the earlier per-project separation was removed; projects survive only as legacy migration input, see [Memory](Memory.md)). **Replaced:** retracting a topic that has sole-linked knowledge notes is refused unless you pass `migrate_to_topic_id` (move them to another active topic) or `force_cascade=true`, rather than cascading implicitly. |
| 1 | User/assistant-only scroll; 90 messages → keep 10; immutable chunks | **Implemented, not yet host-verified:** opt-in capture (off unless `MEMB_SCROLL_CAPTURE=1`), 90 → keep 10 rollover (configurable), credential and size rejection, immutable numbered chunks; see [Hooks](Hooks.md). |
| 1 | Latest user message only; skip under 100 characters and slash commands; dedup resets every seven chunks | **Partial, not yet host-verified:** opt-in retrieval on prompt submit for Claude Code and Codex (not Antigravity), 100-character gate and per-session deduplication (configurable); the exact re-injection rule is in [Hooks](Hooks.md). **Not implemented:** skipping slash commands, and re-injecting a note that was updated after it was injected (T019). Explicit search has its own nonempty/512-byte limits. |
| 2 | Managed `llama-server`, CPU ISA selection, EmbeddingGemma prefixes, Matryoshka dimensions, idle unload | **Replaced / partial:** memb never starts a model server. It can call a loopback llama-server you start (`MEMB_EMBED_PORT`) or run EmbeddingGemma 2 (ONNX) in-process (`MEMB_GEMMA_MODEL_DIR`), with optional Matryoshka truncation (128/256/512/768). No model is shipped in the package. ISA selection and idle unload are **open**. |
| 2 | Query LRU (256 entries), document embedding cache, quantized project working set and version invalidation | **Partial:** quantized (i8) note vectors are cached keyed by model identity and dimension: on the loopback server path only when `MEMB_EMBED_MODEL_ID` is set, and always under the model's identity for the in-process EmbeddingGemma 2 path. A 256-entry query LRU exists only on the loopback server path and only when `MEMB_EMBED_MODEL_ID` is set; the in-process path has no query cache, and a process-static LRU does not help one-shot hook processes. There is no persistent in-RAM working set and no project version key: each search loads the notes and scans their vectors, and `cache_doc_embedding` has no caller (T023). Without a backend, search is lexical. |
| 2 | LanceDB vector ANN + BM25/FTS + hybrid RRF | **Replaced:** hybrid ranking in-process (lexical + quantized vectors, reciprocal rank fusion, lexical fallback); LanceDB is not linked and redb stays authoritative. |
| 2 | One-hop knowledge/claim neighbors with no topic fan-out | **Implemented:** one-hop expansion from the search hits with a result limit that skips inactive notes, checked by the `memb-store` unit test `expansion_excludes_inactive_seeds_and_parents_and_obeys_limit`. That test does not assert the absence of a second hop or of topic fan-out. |
| 3 | Layer 1 summarizes and embeds immutable chunks; Layer 2 runs after sweep or at three uncurated chunks | **Partial:** the daemon sweeps idle scrolls into chunks and stages them; the explicit `memb curate` command asks your configured command-line model for a summary and `explicit_signal` of each staged chunk (Layer 1, T015), embeds the summary (never the conversation text) when an embedding backend is configured, then sends the staged chunks and summaries to the model and records pending proposals (see [Operations](Operations.md)). Summaries cover staged chunks only, and a hook never calls a model. Layer 2 is built (T016): chunk-to-chunk and chunk-to-note links, evidence packets, the three-chunk trigger with a one-hour cooldown, and the curation hash cache. Automatic apply with rollback is built and opt-in (`curator.auto_apply`, T017): per-run limit, no cascade retract, kill switch, audit list and per-proposal rollback of creations, supersessions, retractions and updates. **Open:** unattended-run verification with the real CLIs (T018). Curation from the daemon exists but is off unless `curator.daemon_enabled = true`. |
| 3 | Evidence thresholds: chunk corroboration at 0.72, existing-node match at 0.70, or explicit directive; 30-day staging TTL | **Done for `memb curate`:** chunk-to-chunk 0.72, chunk-to-note 0.70 or an explicit directive qualify a chunk (OR); the `curator_evidence` tool does the same on caller-supplied vectors. Without an embedding backend only directive chunks qualify. The 30-day staging limit (`curator.staging_ttl_days`) is enforced on staged chunks and pending proposals by `curate`, `proposals` and the daemon. |
| 3 | Source chunk pointers, raw drill-down, staging and curator validation | **Partial:** created and updated notes get `properties.source_chunks` stamped by memb; the `scroll_chunk_read` MCP tool returns bounded pages of raw chunk text for review; proposals are validated, host-checked against the chunks actually sent, and need typed approval. A retraction cannot carry a source on the note itself (the proposal record holds it), and raw chunks have no deletion lifecycle (expiry does not delete them). |
| 3 | Per-type CRUD, claim supersede/retract, preservation of multi-parent graph integrity | **Implemented with generic tools:** remember/update/supersede/retract/search/inspect enforce typing and referential integrity, and every change records a revision. The per-type tools of the plan (topic_upsert, knowledge_upsert, claim_add and so on) and topic_list/session_inspect do not exist; their replacement by generic tools has no recorded user approval yet (T024, T021). Rollback beyond single-note updates is **open** (see [Operations](Operations.md)); protected reparenting and revision-scoped edge updates are not claimed. |
| 3 | Direct model APIs and headless CLI backends with recursion guard | **Partial:** only a headless command-line backend exists (`curator.cli_command`, run without a shell, `MEMB_INTERNAL=1` set, bounded time and output, `memb curate` refuses to run when `MEMB_INTERNAL` is set). There are no direct model APIs, a deliberate departure decided by the user on 2026-11-25: the headless model is a CLI so memb handles no credentials. The runner starts the command in a sandbox directory inside a kill-on-close Job Object. `codex exec` (gpt-6-luna, medium) is verified against the real CLI; `agy -p` (gemini-4-hydrogen-medium) is a separate ticket and Claude CLI is not planned. The command receives private conversation text, so consent is your choice of command. |
| Shared design / 3 | Three lifecycle events only (SessionStart, prompt submit, turn end); `MEMD_NO_MEMORY` (now `MEMB_NO_MEMORY`) and ignore directories; no tool/compaction/end-session logs | **Implemented, not yet host-verified:** opt-in capture (`MEMB_SCROLL_CAPTURE=1`), `MEMB_NO_MEMORY`/`MEMB_INTERNAL` kill switches, ignore directories, secret and size rejection, per-host adapters and packaged hook files; see [Hooks](Hooks.md). Claude Code and Codex wire two events (prompt submit, Stop) and Antigravity one (Stop); no SessionStart or BeforeAgent hook exists (T024). Antigravity captures on `Stop` from its transcript (no prompt event, no retrieval). Real model-driven sessions in each host remain **open**. |
| 4 | Routine at 15:45 WIB, 20-hour cooldown, ≥24-hour catch-up; sweep idle >24h and ≥45 messages, keep 10 | **Partial:** `memb daemon` implements this schedule policy, lease and sweep (unit-tested; never run as a long-lived process, and no scheduled task is installed). Restart, wake and long-run behavior are **open**. |
| 4 | Consolidation, incremental compaction, history, graph-consistent rollback and Markdown mirror | **Partial:** revision history (`memb revisions`), rollback of single updates (`memb rollback`) and of whole curation edits including creations, supersessions and retractions (`memb proposals rollback`), and a create-only Markdown mirror exist; see [Operations](Operations.md). Consolidation, compaction and rollback of grouped or lifecycle changes are **open**; deleting a note is not an erasure guarantee. |
| 4 | Optional Python sidecar, zero idle RAM; Windows logon task, not a system service | **Partial:** no sidecar. A reviewed per-user task installer and uninstaller exist (`scripts/install-daemon-task.ps1`, see [Operations](Operations.md)); the task has been registered once on the development machine, and a run at logon and a long unattended run are **open**. |
| Release | Cowork `.plugin`, native AGY and Codex companions (a Desktop `.mcpb` is not a release target) | **Built:** `memb.plugin`, `memb-agy.zip` and `memb-codex.zip` from the shared Windows executable via `scripts/package.py`; native host support must be checked independently. See [verification matrix](Install.md#verification-matrix). |

## Retirement checklist

1. Verify each intended host with synthetic save → cross-host recall → restart → forget → uninstall. Verify that an import actually makes tools callable. Record host version and package hash.
2. Turn every open requirement into tested behavior or obtain the user's explicit approval for a documented replacement or omission. Retain enough detail to reproduce exact phase behavior without the original files.
3. Have Kanban QA review release evidence and this ledger. Do not pass cleanup on archive shape, unit tests, or partial coverage alone.
4. Only then delete the four specifically named `memd-phase1-windows` through `memd-phase4-windows` directories. Confirm exact paths and keep any unrelated files. Do not clean the entire working directory.
