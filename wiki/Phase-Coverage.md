# Phase coverage and retirement gate

This is a requirements ledger, not a release claim. **Implemented** means the local v0.1 implementation exists; native host verification is separate. **Replaced** means the design intention is addressed differently. **Open** means the phase software and notes must be retained until implementation or an approved disposition.

| Source | Requirement | v0.1 disposition |
|---|---|---|
| Shared design / 1 | Windows-first Rust daemon and CLI, one project memory across clients | **Replaced:** one binary, stdio per client, one OS-serialized redb store. The optional foreground `memb daemon` is a loop you start yourself (see [Operations](Operations.md)); the daemon has no network listener, and no scheduled task is installed. (The separate `memb web` inspector is a read-only loopback HTTP listener you start yourself; see [Inspector](Inspector.md).) |
| Shared design / 1 | 2 GiB Win32 Job Object and kill-on-close; 1200/1550/1750 MiB governor thresholds and bounded redb cache | **Partial:** 16 MiB configured redb cache, bounded note/query/frame input; `memb daemon` applies a 2 GiB job-object cap to itself. The governor thresholds and budget tests remain **open** (a pressure classifier exists in `memb-win` but nothing calls it). |
| 1 | Topic/knowledge/claim hierarchy and durable graph | **Implemented:** explicit project, typed parent links, atomic updates, monotonic IDs. **Replaced:** retracting a topic that has sole-linked knowledge notes is refused unless you pass `migrate_to_topic_id` (move them to another active topic) or `force_cascade=true`, rather than cascading implicitly. |
| 1 | User/assistant-only scroll; 90 messages → keep 10; immutable chunks | **Implemented, not yet host-verified:** opt-in capture (off unless `MEMB_SCROLL_CAPTURE=1`), 90 → keep 10 rollover (configurable), credential and size rejection, immutable numbered chunks; see [Hooks](Hooks.md). |
| 1 | Latest user message only; skip under 100 characters and slash commands; dedup resets every seven chunks | **Implemented, not yet host-verified:** opt-in retrieval on prompt submit for Claude Code and Codex (not Antigravity), 100-character gate and per-session deduplication (configurable); the exact re-injection rule is in [Hooks](Hooks.md). Explicit search has its own nonempty/512-byte limits. |
| 2 | Managed `llama-server`, CPU ISA selection, EmbeddingGemma prefixes, Matryoshka dimensions, idle unload | **Replaced / partial:** memb never starts a model server. It can call a loopback llama-server you start (`MEMB_EMBED_PORT`) or run EmbeddingGemma 2 (ONNX) in-process (`MEMB_GEMMA_MODEL_DIR`), with optional Matryoshka truncation (128/256/512/768). No model is shipped in the package. ISA selection and idle unload are **open**. |
| 2 | Query LRU (256 entries), document embedding cache, quantized project working set and version invalidation | **Partial:** quantized (i8) note vectors are cached keyed by model identity and dimension: on the loopback server path only when `MEMB_EMBED_MODEL_ID` is set, and always under the model's identity for the in-process EmbeddingGemma 2 path. A 256-entry query LRU exists only on the loopback server path and only when `MEMB_EMBED_MODEL_ID` is set; the in-process path has no query cache. Without a backend, search is lexical. |
| 2 | LanceDB vector ANN + BM25/FTS + hybrid RRF | **Replaced:** hybrid ranking in-process (lexical + quantized vectors, reciprocal rank fusion, lexical fallback); LanceDB is not linked and redb stays authoritative. |
| 2 | One-hop knowledge/claim neighbors with no topic fan-out | **Implemented:** one-hop expansion from the search hits with a result limit that skips inactive notes, checked by the `memb-store` unit test `expansion_excludes_inactive_seeds_and_parents_and_obeys_limit`. That test does not assert the absence of a second hop or of topic fan-out. |
| 3 | Layer 1 summarizes and embeds immutable chunks; Layer 2 runs after sweep or at three uncurated chunks | **Partial:** the daemon can sweep idle scrolls into chunks and stage chunks as evidence; it does not summarize, embed or write notes. Model-driven curation is **open**. |
| 3 | Evidence thresholds: chunk corroboration at 0.72, existing-node match at 0.70, or explicit directive; 30-day staging TTL | **Open:** detailed Phase 3 uses OR between these routes; the summary's AND shorthand conflicts. Retain OR as the proposed acceptance rule. |
| 3 | Source chunk pointers, raw drill-down, staging and curator validation | **Partial:** notes store only user-approved text; the `scroll_chunk_read` MCP tool returns bounded pages of raw chunk text for review. Source pointers on notes, a staging TTL and automatic curator validation are **open**, and raw chunks need a deletion lifecycle. |
| 3 | Per-type CRUD, claim supersede/retract, preservation of multi-parent graph integrity | **Implemented:** remember/update/supersede/retract/search/inspect enforce typing and referential integrity, and every change records a revision. Rollback beyond single-note updates is **open** (see [Operations](Operations.md)); protected reparenting and revision-scoped edge updates are not claimed. |
| 3 | Direct model APIs and headless CLI backends with recursion guard | **Open:** no providers, scripts, credentials or cloud transmission in the runtime. Backend use and user consent must be verified independently. |
| Shared design / 3 | Three lifecycle events only; `MEMD_NO_MEMORY` and ignore directories; no tool/compaction/end-session logs | **Implemented, not yet host-verified:** opt-in capture (`MEMB_SCROLL_CAPTURE=1`), `MEMB_NO_MEMORY`/`MEMB_INTERNAL` kill switches, ignore directories, secret and size rejection, per-host adapters and packaged hook files; see [Hooks](Hooks.md). Antigravity captures on `Stop` from its transcript (no prompt event, no retrieval). Real model-driven sessions in each host remain **open**. |
| 4 | Routine at 15:45 WIB, 20-hour cooldown, ≥24-hour catch-up; sweep idle >24h and ≥45 messages, keep 10 | **Partial:** `memb daemon` implements this schedule policy, lease and sweep (unit-tested; never run as a long-lived process, and no scheduled task is installed). Restart, wake and long-run behavior are **open**. |
| 4 | Consolidation, incremental compaction, history, graph-consistent rollback and Markdown mirror | **Partial:** revision history (`memb revisions`), single-note update rollback and a create-only Markdown mirror exist; see [Operations](Operations.md). | 4 | Optional Python sidecar, zero idle RAM; Windows logon task, not a system service | **Open:** no sidecar and no installed task; the foreground daemon is started by you. Task installation needs review and your approval. |
| Release | Cowork `.plugin`, native AGY and Codex companions (a Desktop `.mcpb` is not a release target) | **Built:** `memb.plugin`, `memb-agy.zip` and `memb-codex.zip` from the shared Windows executable via `scripts/package.py`; native host support must be checked independently. See [verification matrix](Install.md#verification-matrix). |

## Retirement checklist

1. Verify each intended host with synthetic save → cross-host recall → restart → forget → uninstall. Verify that an import actually makes tools callable. Record host version and package hash.
2. Turn every open requirement into tested behavior or obtain the user's explicit approval for a documented replacement or omission. Retain enough detail to reproduce exact phase behavior without the original files.
3. Have Kanban QA review release evidence and this ledger. Do not pass cleanup on archive shape, unit tests, or partial coverage alone.
4. Only then delete the four specifically named `memd-phase1-windows` through `memd-phase4-windows` directories. Confirm exact paths and keep any unrelated files. Do not clean the entire working directory.
