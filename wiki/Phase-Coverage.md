# Phase coverage and retirement gate

This is a requirements ledger, not a release claim. **Implemented** means the current (workspace 0.7.1) implementation exists; native host verification is separate. **Replaced** means the design intention is addressed differently. **Open** means the phase software and notes must be retained until implementation or an approved disposition.

| Source | Requirement | Current disposition |
|---|---|---|
| Shared design / 1 | Windows-first Rust daemon and CLI, one project memory across clients | **Replaced:** one binary, stdio per client, one OS-serialized redb store. The optional foreground `memb daemon` is a loop you start yourself (see [Operations](Operations.md)); the daemon has no network listener. A per-user scheduled task for it has been registered on the development machine (row 24); memb and the packages never register one themselves. (The separate `memb web` inspector is a read-only loopback HTTP listener you start yourself; see [Inspector](Inspector.md).) |
| Shared design / 1 | 2 GiB Win32 Job Object and kill-on-close; 1200/1550/1750 MiB governor thresholds and bounded redb cache | **Done (T020):** 16 MiB configured redb cache, bounded note/query/frame input; `memb daemon` and `memb mcp` put themselves in a job object with a **job-wide** 2 GiB limit (`JOB_OBJECT_LIMIT_JOB_MEMORY`) and **kill-on-close** (everything the process starts afterwards shares the cap and is stopped with it; tested with a real child). Hooks do not attach, by decision: they are short-lived and bounded (16 KiB messages), and a job per prompt adds cost for no gain. The governor thresholds are wired: every 15 s a governor thread in the daemon and the MCP server reads the process's private memory; from 1550 MiB it drops the embedding model and the query cache, and the daemon pauses background work (routine, curation) at 1750 MiB. The 1200 MiB warn level is only classified. Budget tests cover each threshold. |
| 1 | Topic/knowledge/claim hierarchy and durable graph | **Implemented:** typed parent links, atomic updates, monotonic IDs, in one unified graph (the earlier per-project separation was removed; projects survive only as legacy migration input, see [Memory](Memory.md)). **Replaced:** retracting a topic that has sole-linked knowledge notes is refused unless you pass `migrate_to_topic_id` (move them to another active topic) or `force_cascade=true`, rather than cascading implicitly. |

| 1 | Latest user message only; skip under 100 characters and slash commands; dedup resets every seven chunks | **Done (T019):** opt-in retrieval on prompt submit for Claude Code and Codex (not Antigravity); the 100-character gate; slash commands (`^/[A-Za-z0-9_-]+`, however long) never retrieve but are still recorded in the scroll; per-session deduplication (configurable) that also re-injects a note once after it was updated, in the same epoch; the exact rules are in [Hooks](Hooks.md). | 2 | Managed `llama-server`, CPU ISA selection, EmbeddingGemma prefixes, Matryoshka dimensions, idle unload | **Replaced / partial:** memb never starts a model server. It can call a loopback llama-server you start (`MEMB_EMBED_PORT`) or run EmbeddingGemma 2 (ONNX) in-process (`MEMB_GEMMA_MODEL_DIR`), with optional Matryoshka truncation (128/256/512/768). No model is shipped in the package. **Done (T020):** the in-process model is unloaded after sitting idle (300 s on the CpuLite tier, 600 s on CpuBalanced; the next search loads it again) and at once under memory pressure. A hardware prober (AVX-512 or AVX2+FMA, physical cores, installed RAM) chooses the tier: CpuBalanced needs AVX2/AVX-512, 8 physical cores and 16 GB, otherwise CpuLite. **Replaced:** there is no GPU tier (the embedder is a CPU-only ONNX model, so a GPU could not be used), no GGUF quantization choice and no session-start warm-up (the model loads on first use). The tier only sets the idle timer; the embedding width stays your `embeddings.mrl_dim`. |
| 2 | Query LRU (256 entries), document embedding cache, quantized project working set and version invalidation | **Partial:** quantized (i8) note vectors are cached keyed by model identity and dimension: on the loopback server path only when `MEMB_EMBED_MODEL_ID` is set, and always under the model's identity for the in-process EmbeddingGemma 2 path. A 256-entry query LRU exists only on the loopback server path and only when `MEMB_EMBED_MODEL_ID` is set; the in-process path has no query cache, and a process-static LRU does not help one-shot hook processes, so the query LRU is recorded as **stdio-only by decision (T019)**: a persistent on-disk query cache would add writes to every hook for no measurable gain (hook work is below the process start time, see Hooks). There is no persistent in-RAM working set and no project version key: each search loads the notes and scans their vectors, and `cache_doc_embedding` has no caller (T023). Without a backend, search is lexical. |
| 2 | LanceDB vector ANN + BM25/FTS + hybrid RRF | **Replaced:** hybrid ranking in-process (lexical + quantized vectors, reciprocal rank fusion, lexical fallback); LanceDB is not linked and redb stays authoritative. |
| 2 | One-hop knowledge/claim neighbors with no topic fan-out | **Implemented:** one-hop expansion from the search hits with a result limit that skips inactive notes, checked by the `memb-store` unit test `expansion_excludes_inactive_seeds_and_parents_and_obeys_limit`. That test does not assert the absence of a second hop or of topic fan-out. |
| 3 | Layer 1 summarizes and embeds immutable chunks; Layer 2 runs after sweep or at three uncurated chunks | **Partial:** the daemon sweeps idle scrolls into chunks and stages them; the explicit `memb curate` command asks your configured command-line model for a summary and `explicit_signal` of each staged chunk (Layer 1, T015), embeds the summary (never the conversation text) when an embedding backend is configured, then sends the staged chunks and summaries to the model and records pending proposals (see [Operations](Operations.md)). Summaries cover staged chunks only, and a hook never calls a model. Layer 2 is built (T016): chunk-to-chunk and chunk-to-note links, evidence packets, the three-chunk trigger with a one-hour cooldown, and the curation hash cache. Automatic apply with rollback is built and opt-in (`curator.auto_apply`, T017): per-run limit, no cascade retract, kill switch, audit list and per-proposal rollback of creations, supersessions, retractions and updates. **Open:** unattended-run verification with the real CLIs (T018). Curation from the daemon exists but is off unless `curator.daemon_enabled = true`. |

## Retirement checklist

1. Verify each intended host with synthetic save → cross-host recall → restart → forget → uninstall. Verify that an import actually makes tools callable. Record host version and package hash.
2. Turn every open requirement into tested behavior or obtain the user's explicit approval for a documented replacement or omission. Retain enough detail to reproduce exact phase behavior without the original files.
3. Have Kanban QA review release evidence and this ledger. Do not pass cleanup on archive shape, unit tests, or partial coverage alone.
4. Only then delete the four specifically named `memd-phase1-windows` through `memd-phase4-windows` directories. Confirm exact paths and keep any unrelated files. Do not clean the entire working directory.
